1) End-to-end pipeline map

python -m sloth run --input <folder> [--dry-run]
    ├─ discover_images()           (ingest.py)
    │    ├─ include: jpg/jpeg/png
    │    ├─ skip: _sloth_review/, manifest-tracked files
    │    └─ warn: heic/heif
    │
    ├─ filter_images()             (filters.py)
    │    ├─ near-duplicates via phash distance
    │    ├─ blur via Laplacian variance
    │    ├─ dark/overexposed via grayscale mean
    │    └─ screenshot flag only (not auto-junk)
    │
    ├─ review_survivors()          (review.py -> gemma.py)
    │    ├─ only rule survivors go to Gemma
    │    ├─ JSON schema-enforced response
    │    ├─ retries on invalid output
    │    └─ fallback: needs_review
    │
    ├─ decisions.jsonl append      (rules + gemma for every photo)
    ├─ move_to_review()            (mover.py, stage=rules/gemma)
    ├─ build_journal_from_run()    (journal.py + factcheck.py)
    ├─ latest_run.json snapshot
    └─ summary line output

Dry-run mode avoids file moves and still computes decision summaries.

Execution model

  • Deterministic rules first: fast and explainable pruning.
  • LLM second: only on survivors to reduce token/runtime cost.
  • Audit trail always: per-photo decision rows regardless of path.
  • No destructive delete: move + undo supports reversible workflow.
Important: local inference speed depends on Ollama availability/model load. For CI and offline smoke tests, fake/heuristic paths avoid hard blocking.

3) Classical rule engine details (non-LLM)

Duplicate detection with perceptual hash

Uses imagehash.phash and configurable Hamming distance (duplicate_hash_distance). Connected duplicates form groups; the sharpest image is kept, others become junk: duplicate.

Blur detection with Laplacian variance

Converts to grayscale, resizes to 512px, computes Laplacian variance. Below threshold => blurry.

Brightness heuristics

Mean grayscale intensity below dark threshold => dark; above bright threshold => overexposed.

Screenshot marker

PNG + filename/dimensions pattern sets is_screenshot=True but does not force junk. That decision is deferred to Gemma policy.

4) ML/AI core: Gemma through Ollama

Inference contract
  • Image resized to configured size (default 768).
  • ollama.chat(..., options={"temperature": 0}).
  • format= Pydantic JSON schema (strict output structure).
  • Response validated before use.
Reliability path (invalid JSON/schema mismatch)
  1. Attempt request.
  2. If parse/validation fails, retry (up to 2 retries).
  3. If still failing: return needs_review fallback record.
Latency tracking

Per-call durations are collected and aggregated into seconds for each decision, then surfaced into run summaries/eval.

Environment toggles
  • OLLAMA_HOST: custom Ollama endpoint.
  • SLOTH_FAKE_GEMMA=1: local heuristic review path (CI/smoke mode).

5) Journal generation + fact-check

kept photos
  └─ group by date
      └─ group by place
          └─ facts payload (time, place, captions only)
              └─ Gemma draft (80-150 words, first person)
                   ├─ factcheck pass     -> status=pass
                   ├─ fail + retry once  -> status=retried (if pass)
                   └─ fail again         -> status=template fallback

Output files are written to journal/YYYY-MM-DD.md, and status events are logged in journal/journal_log.jsonl.

8) AI/ML quality controls in this design

  • Schema validation: constrains LLM output surface.
  • Retry budget: limits malformed output loops.
  • Fact-check gate: blocks unsupported journal claims.
  • Template fallback: guarantees non-empty output even under model failure.
  • Evaluation script: tracks precision/recall and decision-source split.
